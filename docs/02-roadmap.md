# 研发路线图

## 推进原则

采用“需求基线—原型与设计—可运行骨架—业务迭代—系统验证—试运行”的节奏。每个阶段都产出可评审、可验收的成果，不以代码量作为阶段完成标准。

## 阶段与交付物

| 阶段 | 主要工作 | 交付物 | 完成条件 |
| --- | --- | --- | --- |
| 1. 需求基线 | 角色访谈、现状流程、范围分期、业务规则、验收标准 | SRS、流程图、术语表、待确认清单、需求追踪矩阵 | 关键角色确认一期范围和验收场景 |
| 2. 产品与概要设计 | 信息架构、页面原型、领域划分、部署和安全设计 | 原型、概要设计、权限矩阵、架构图 | 核心流程可通过原型走通 |
| 3. 详细设计 | 数据模型、API、状态机、编码规则、审计与备份设计 | ER 图、数据字典、OpenAPI、状态流转表 | 设计评审通过且需求可追踪 |
| 4. 工程骨架 | 前后端工程、数据库迁移、认证授权、日志、CI | 可运行开发环境和基础平台 | 一键启动，登录、权限、迁移和测试可用 |
| 5. 一期迭代 | 按模块实现并持续联调 | 财务、物料、文件、报告、组织权限 | 每模块满足验收场景和自动化测试门槛 |
| 6. 系统测试 | 功能、接口、权限、性能、安全、备份恢复测试 | 测试计划、用例、报告、缺陷清单 | 阻断/严重缺陷清零，关键指标达标 |
| 7. UAT 与试运行 | 数据初始化、培训、用户验收、并行试运行 | UAT 记录、培训材料、上线和回退方案 | 业务负责人签署上线意见 |
| 8. 上线运维 | 部署、监控、备份、应急演练和持续改进 | 运维手册、应急预案、巡检与版本机制 | 稳定运行并完成首次恢复演练 |

## 一期建议迭代

1. 迭代 0：工程骨架、组织用户、RBAC、字典、审计日志、文件存储、通知框架。
2. 迭代 1：物料主数据、采购申请、验收入库、领用出库、批次库存和预警。
3. 迭代 2：计价规则、费用试算、收费确认、收款与欠款统计。
4. 迭代 3：文件版本、审核发布、权限和复审提醒。
5. 迭代 4：报告模板、报告状态流、审核批准、导出、用印和归档。
6. 迭代 5：统计报表、数据导入导出、性能优化、安全加固和系统验收。

## 每个迭代的质量门槛

- 需求有唯一编号，并关联设计、代码提交、测试用例和验收结果。
- 后端包含单元测试和接口/集成测试；核心状态流和权限必须自动化覆盖。
- 前端核心页面具备组件测试，关键闭环具备端到端测试。
- 数据库变更通过迁移脚本管理，禁止只在开发库手工改表。
- 关键操作写入不可由普通用户修改的审计日志。
- 合并前执行格式检查、静态检查、测试和构建。
- 阶段结束进行可演示验收并更新风险清单。
