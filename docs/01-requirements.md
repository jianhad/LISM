# 需求规格说明（基线草案 V0.1）

## 1. 建设目标

建设一个浏览器访问的实验室信息管理系统，实现业务、人员、物资、文件和报告数据的统一管理；确保关键操作全过程留痕、数据可追溯、记录可长期保存，并具备备份、预警、统计、导入导出及扩展集成能力。

合规目标：支持 CMA、CNAS 和 ISO/IEC 17025 管理要求。系统只能提供合规能力，最终是否合规仍取决于实验室制度、流程配置、验证记录和实际执行。

## 2. 用户与角色

初始角色建议如下，正式权限以岗位调研结果为准：

| 角色 | 主要职责 |
| --- | --- |
| 系统管理员 | 组织、用户、角色、参数、字典、接口和系统运维 |
| 实验室负责人 | 业务总览、审批、资源调度、报告批准 |
| 财务/核算人员 | 价格维护、费用核算、收款、欠款和成本统计 |
| 采购人员 | 采购申请汇总、采购处理、供应商信息维护 |
| 库管人员 | 验收、入库、出库、盘点、处置和库存预警 |
| 检测人员 | 领用物料、使用文件、填写记录、生成报告数据 |
| 报告编制人员 | 选择模板、编制、拆分、导出报告 |
| 审核/批准人员 | 查看报告、原始记录及关联数据，审核或退回 |
| 文件管理员 | 文件上传、版本、审核、发布、回收和权限维护 |
| 质量管理人员 | 监督检查、用印审核、质量记录和审计查询 |
| 档案管理员 | 报告立档、位置、期限、移交和验收 |
| 只读/审计人员 | 按授权范围查询数据、日志及统计报表 |

## 3. 一期功能需求

### 3.1 平台与权限

- 维护单位、部门、岗位、用户、角色及数据权限。
- 功能权限至少细化到菜单和操作按钮；敏感数据还需支持数据范围权限。
- 支持账号启停、密码策略、登录失败限制、会话失效和操作审计。
- 用户工作台仅展示本人有权访问的菜单、待办、提醒和统计。
- 所有审批类业务采用可配置状态流转，并保存操作者、时间、意见及前后值。

### 3.2 财务管理

- 维护检测类型、检测项目、计价单位、收费单价、折扣和生效期限。
- 价目支持新增、修改和删除；已被收费单引用的检测项目必须锁定，不允许修改或删除，以保证历史收费单的项目与价格快照可追溯。
- 根据业务样品数量与分析项目自动试算费用，核算人员确认后形成收费单。
- 收费单待确认时允许修改和删除；确认后进入待收款，未发生收款前允许退回待确认重新编辑。
- 财务界面状态使用中文展示，数据库及接口内部可使用稳定的英文状态码；新建收费单只能选择当前状态为启用的价目项目。
- 登记收款、退款或调整，支持部分收款、未收款和欠款统计。
- 根据预设单项成本初步核算业务成本。
- 生成、打印和导出收费单、对账及统计报表。

### 3.3 物料管理

- 建立试剂、耗材、标准物质、标准试剂及危险品主数据和批次库存。
- 支持采购申请、汇总、审批、采购结果登记。
- 支持验收、入库、领用审批、出库、退库、调拨、盘点、报损和处置。
- 库存采用批次管理，记录有效期、供应商、数量、单位、价格和存放位置。
- 统计期初、本期入库、本期出库、期末库存、加权平均价格和库存价值。
- 对低库存、临期和过期进行预警。
- 危化、危废、易制毒、易制爆物资建立分类专项台账；监控设施对接列为扩展接口。
- 支持标签生成与打印，并保留物料流转审计轨迹。

### 3.4 文件管理

- 分类管理体系文件、记录表格、标准文本和常用文件。
- 支持文件上传、版本号、修订说明、审核、发布、作废、回收和历史版本查询。
- 按部门、角色、用户配置浏览和下载权限。
- 文件发布、替换、下载和作废均记录审计日志。
- 对需复审文件按日期生成待办和提醒。

### 3.5 分析报告管理

- 维护可导入、导出的报告模板，模板与业务数据分离。
- 支持按报告类型选择模板，生成预览并导出 Word、Excel、PDF。
- 支持报告编制、提交、审核、批准、退回、打印、发放和归档状态流转。
- 审核与批准人员可查看关联原始记录、实验数据和操作轨迹。
- 支持报告拆分、含量单位转换及中英文项目对照。
- 支持电子印章位置控制、用印审批、报告加密和防篡改校验；CA 认证作为独立集成项。
- 记录立档日期、位置、人员和有效期，预留档案系统交互接口。
- 支持按编号、单位、项目、时间、状态等条件查询与统计。

### 3.6 通知、统计与开放能力

- 统一待办中心，支持站内消息；短信和邮件通过可插拔通道接入。
- 一期预警包括库存不足、物料临期、文件复审、报告超期和待审批提醒。
- 报表支持查询、打印、Excel/PDF 导出；复杂自定义报表采用独立报表能力。
- 提供受控的数据导入、字段映射、批量校验和错误报告。
- 对外接口采用版本化 API，记录调用方、时间、结果和错误信息。

## 4. 二期及扩展范围

- 委托受理、任务分派、采样、样品交接、前处理、检测、复核全过程。
- 采测分离模式和每批不超过 30 个样品的快速交接目标。
- 空白、盲样、加标、平行等质量控制方案及质量趋势分析。
- 设备维修、保养、校准、计量确认、点检、封存、报废和量值溯源。
- 人员培训、考核、能力确认、授权和持续能力确认提醒。
- 仪器数据采集配置、文件解析、字段映射及新仪器接入。
- 按环境要素、站位、时间、项目、人员等维度的数据统计与趋势分析。

这些能力在原始文档的总体目标或功能梳理表中出现，但缺少足够业务细节，不建议未经调研直接编码。

## 5. 非功能需求

| 类别 | 基线要求 |
| --- | --- |
| 架构 | B/S 架构，前后端分离，模块化设计，优先模块化单体并保留服务拆分边界 |
| 浏览器 | 支持当前主流 Chromium 浏览器；Firefox 兼容性按项目验收环境确认 |
| 安全 | TLS、最小权限、敏感字段保护、文件访问鉴权、防越权、防注入、审计日志 |
| 可追溯 | 关键数据保存创建、修改、审核、批准、作废的人员、时间、原因及变更前后值 |
| 可靠性 | 数据库定时备份、异地备份能力、恢复演练和备份失败告警 |
| 数据 | 业务记录原则上逻辑删除；已批准或已归档记录禁止直接覆盖修改 |
| 性能 | 普通查询在约定数据量下 P95 不高于 2 秒；大报表采用异步生成 |
| 可维护性 | 配置、字典、模板和通知通道可扩展；接口和数据库变更纳入版本管理 |
| 可观测性 | 应用日志、审计日志、错误追踪、健康检查和关键指标监控 |
| 导出 | 支持 PDF/XLSX；报告按模板能力支持 DOCX |

## 6. 核心验收场景

1. 管理员创建单位、部门、用户和角色后，不同角色只能看到并操作被授权功能。
2. 财务人员配置价格后，系统可根据样品和项目生成费用，登记部分收款并统计欠款。
3. 采购申请审批后完成验收入库；领用出库后库存正确变化并留下批次流转记录。
4. 低库存或物料临期时生成提醒，处理后可追踪提醒状态。
5. 文件经过起草、审核、发布后可按权限浏览；新版本发布后旧版本仍可追溯。
6. 报告由模板生成，经编制、审核、批准、用印、发放和归档，全过程不可无痕修改。
7. 报告可导出 PDF，系统可验证其对应业务版本和文件完整性。
8. 管理人员可查询关键业务统计并导出，所有敏感导出均有审计记录。
9. 备份任务可执行、可告警，并通过恢复演练证明数据能够恢复。

## 7. 范围边界

- 一期不自行实现通用 Office 编辑器、CA 平台、短信网关、硬件监控平台或仪器厂商协议，采用成熟组件或接口集成。
- 电子签章是否具备法律效力取决于选用的 CA/电子签章服务及单位制度。
- 报表模板“任意自定义”必须限定支持的字段、表达式和版式范围。
- 历史数据迁移需单独盘点数据源、质量、映射规则和验收办法。

## 8. 已确认的项目约束

- 一期接受本文第 3 节建议范围。
- 部署环境为内网，要求适配国产化软硬件环境。
- 实际使用人数预计不超过 100 人，系统容量按不少于 200 个并发访问用户设计与验证。
- 一期不对接电子签章、短信、邮件、统一身份认证或外部财务系统。
- 一期必须提供完整的自主用户、角色、功能权限和数据权限管理能力。
- 暂无现行单据和报告模板，系统先提供内置标准模板、模板版本管理和后续配置能力。
- 国产化的具体 CPU、操作系统、数据库、中间件和浏览器品牌尚待确定，因此代码与部署应避免绑定单一厂商特性。
