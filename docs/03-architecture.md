# 技术架构草案（V0.1）

## 1. 架构决策

文档要求 Java 服务端和 B/S 架构。初期建议采用“模块化单体 + 明确领域边界”，而不是立即拆成大量微服务。该方案部署简单、事务一致性清晰，适合从零建设；当仪器接入、报表任务或通知规模增长时，再按边界拆分独立服务。

建议技术栈：

| 层次 | 建议方案 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus |
| 后端 | Java 21、Spring Boot 3、Spring Security、Jakarta Validation |
| 数据访问 | MyBatis-Plus 或 Spring Data JPA，团队二选一后统一；Flyway 管理迁移 |
| 数据库 | 开发基线采用 PostgreSQL 兼容 SQL；生产优先适配 openGauss，若甲方指定达梦/人大金仓则通过兼容层和专项验证切换 |
| 缓存/任务 | Redis；异步任务初期使用受控任务表和调度器，复杂后再引入消息队列 |
| 文件存储 | MinIO/S3 兼容对象存储，文件元数据和哈希保存在数据库 |
| 报表 | DOCX 模板 + PDF 转换；统计导出使用 XLSX；复杂报表引擎通过适配层接入 |
| API | REST + OpenAPI 3，统一错误码、分页、审计上下文和幂等策略 |
| 测试 | JUnit 5、Testcontainers、Spring Boot Test、Vitest、Playwright |
| 部署 | Docker Compose 用于开发/测试；生产支持国产 CPU、麒麟/统信操作系统上的容器或规范化虚拟机部署 |

## 2. 逻辑模块

- `identity`：单位、部门、岗位、用户、角色、权限、登录与数据范围。
- `workflow`：审批定义、业务状态流、待办、意见和流转历史。
- `finance`：价目、费用试算、收费单、收款、欠款和成本。
- `inventory`：物料、批次、采购、验收、库存流水、盘点和预警。
- `document`：体系文件、版本、审核发布、权限和复审。
- `report`：报告模板、实例、编制审核批准、导出、用印、发放和归档。
- `notification`：站内信、短信/邮件通道和发送记录。
- `integration`：数据导入导出、档案、CA、仪器和第三方接口适配。
- `audit`：业务变更审计、安全事件和导出/下载审计。
- `platform`：字典、参数、编号规则、附件、定时任务和健康检查。

## 3. 数据与审计原则

- 业务主表使用稳定的内部 ID，展示编号由可配置编号规则生成。
- 金额使用定点小数，数量同时保存单位；时间统一存储时区明确的时间值。
- 库存通过不可变流水计算和校验，禁止直接修改现存量而不产生业务单据。
- 已审核/批准数据采用版本化或更正流程，不允许覆盖历史事实。
- 附件保存 SHA-256、大小、MIME、存储键、上传人和业务关联信息。
- 审计记录包含主体、动作、对象、时间、来源、结果、原因和必要的变更摘要。
- 审计与业务日志分离；普通业务管理员无权删除或修改审计记录。

## 4. 安全设计基线

- 默认使用单位账号密码登录，预留统一身份认证接口。
- RBAC 控制功能权限，部门/本人/指定范围控制数据权限。
- 后端对每个受保护接口执行授权，不能仅依赖前端隐藏按钮。
- 敏感配置放在外部密钥或环境配置中，不进入源码。
- 文件下载使用授权校验和短时访问机制；上传执行类型、大小及恶意内容检查。
- 对登录、权限变更、审批、导出、打印、用印和归档执行重点审计。
- 定期备份数据库和对象文件，异地保存并执行可证明的恢复演练。

## 5. 建议工程结构

```text
LIMS/
├─ backend/                 # Spring Boot 多模块或单仓模块化后端
├─ frontend/                # Vue 3 管理端
├─ deploy/                  # 本地与环境部署配置
├─ docs/                    # 需求、设计、接口、测试和运维文档
└─ scripts/                 # 初始化和受控运维脚本
```

在 P0 需求确认前暂不生成大规模业务代码，以免关键业务规则变化造成返工；但下一阶段可先建立不依赖业务细节的工程骨架和质量工具链。

## 6. 国产化与容量基线

- Java、前端静态资源和标准 SQL 不依赖 x86 专属能力，目标兼容海光、鲲鹏等常见国产 CPU。
- 服务器操作系统目标兼容银河麒麟和统信 UOS Server，具体版本在部署前纳入兼容性测试矩阵。
- 应用服务器优先使用内嵌 Web 容器，减少对商业中间件的绑定；如指定东方通、宝兰德等中间件，另做部署适配。
- 数据访问层禁止散落厂商专属 SQL；分页、日期、JSON、序列和全文检索等差异集中封装。
- 文件存储提供本地受控目录与 S3 兼容对象存储两种实现，内网无对象存储时仍可部署。
- 系统按不少于 200 并发访问设计。验收压测应覆盖登录、工作台查询、库存查询、文件下载、报告列表及混合业务场景。
- 初始性能目标：普通 API P95 不高于 2 秒，复杂统计 P95 不高于 5 秒，大文件和报告生成采用异步任务。
